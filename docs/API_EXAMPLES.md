# Transaction Ledger API Examples

This document contains verified, copy-pasteable examples for every endpoint of
the transaction ledger API. Every request and response below was executed
against the running API at `http://localhost:3000` (Compose project
`ledger-assignment`) and matches the implemented contract.

## Conventions

- Requests and responses use JSON. Requests with a body include the header
  `Content-Type: application/json`.
- Every monetary amount is a canonical decimal string of integer minor units.
  For example `"1500"` means 1500 minor units, which is $15.00 USD.
- The only supported currency is `USD`.
- `POST /transfers` requires the `Idempotency-Key` header. Header names are
  case-insensitive on the wire.
- `accountId`, `transferId`, `createdAt`, and `requestId` are generated by the
  server. They are dynamic and will differ on every run. The identifiers below
  are representative values that stay consistent across the related examples.
  `requestId` follows the `req-<counter>` format and changes on every request.
- Every error response uses the same shape, for example:

  ```json
  {
    "code": "UNKNOWN_ACCOUNT",
    "message": "Referenced account does not exist.",
    "requestId": "req-2k3m9a1b"
  }
  ```

## Ledger used by these examples

| Step                  | Amount | Account A balance | Account B balance |
| --------------------- | ------ | ----------------- | ----------------- |
| Account A opened      | 5000   | 5000              | -                 |
| Account B opened      | 0      | 5000              | 0                 |
| Transfer A to B       | 1500   | 3500              | 1500              |
| Exact retry of A to B | 1500   | 3500              | 1500              |
| Transfer B to A       | 500    | 4000              | 1000              |

Total money is conserved: the sum of both balances is `5000` before and after
every transfer.

## 1. Create the first account

Create a source account with a non-zero USD opening balance of 5000 minor units
($50.00).

```sh
curl -sS -X POST http://localhost:3000/accounts \
  -H 'Content-Type: application/json' \
  -d '{"currency":"USD","initialBalance":"5000"}'
```

`HTTP/1.1 201 Created`

```json
{
  "accountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
  "balance": "5000",
  "currency": "USD",
  "createdAt": "2026-08-08T10:00:00.000Z"
}
```

## 2. Create a second account

Create a destination account with a zero opening balance.

```sh
curl -sS -X POST http://localhost:3000/accounts \
  -H 'Content-Type: application/json' \
  -d '{"currency":"USD","initialBalance":"0"}'
```

`HTTP/1.1 201 Created`

```json
{
  "accountId": "7b8c9d0e-1f2a-4b3c-9d4e-5f6a7b8c9d0e",
  "balance": "0",
  "currency": "USD",
  "createdAt": "2026-08-08T10:00:01.000Z"
}
```

## 3. Transfer funds using an idempotency key

Transfer 1500 minor units ($15.00) from the first account to the second. The
`Idempotency-Key` header is required and uniquely identifies this logical
transfer.

```sh
curl -sS -X POST http://localhost:3000/transfers \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: transfer.20260808:checking-to-savings-001' \
  -d '{
    "sourceAccountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
    "destinationAccountId": "7b8c9d0e-1f2a-4b3c-9d4e-5f6a7b8c9d0e",
    "amount": "1500",
    "currency": "USD"
  }'
```

`HTTP/1.1 201 Created`

```json
{
  "transferId": "1a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
  "sourceAccountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
  "destinationAccountId": "7b8c9d0e-1f2a-4b3c-9d4e-5f6a7b8c9d0e",
  "amount": "1500",
  "currency": "USD",
  "status": "completed",
  "createdAt": "2026-08-08T10:05:00.000Z"
}
```

## 5. Prove the retry returns the original result and does not move money twice

An exact retry returns the original persisted transfer: the `transferId`,
`createdAt`, and every other field are identical to example 3, and the success
status remains `201 Created`. There is no replay indicator in the response; the
identical body is the proof. The retry does not execute the balance updates
again.

Retrieve both balances to confirm money moved exactly once:

```sh
curl -sS http://localhost:3000/accounts/3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b/balance
```

`HTTP/1.1 200 OK`

```json
{
  "accountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
  "balance": "3500",
  "currency": "USD"
}
```

```sh
curl -sS http://localhost:3000/accounts/7b8c9d0e-1f2a-4b3c-9d4e-5f6a7b8c9d0e/balance
```

`HTTP/1.1 200 OK`

```json
{
  "accountId": "7b8c9d0e-1f2a-4b3c-9d4e-5f6a7b8c9d0e",
  "balance": "1500",
  "currency": "USD"
}
```

The source was debited `1500` (5000 -> 3500) and the destination was credited
`1500` (0 -> 1500). Had the retry moved money a second time, these balances
would be `2000` and `3000`. The total remains `5000`, so no money was created
or destroyed.

## 8. Insufficient funds

The first account now holds 4000 minor units. A transfer of 5000 minor units
must fail with `422 Unprocessable Content` and `INSUFFICIENT_FUNDS`, and it
must change neither account balance.

```sh
curl -sS -X POST http://localhost:3000/transfers \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: transfer.20260808:insufficient-funds-001' \
  -d '{
    "sourceAccountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
    "destinationAccountId": "7b8c9d0e-1f2a-4b3c-9d4e-5f6a7b8c9d0e",
    "amount": "5000",
    "currency": "USD"
  }'
```

`HTTP/1.1 422 Unprocessable Content`

```json
{
  "code": "INSUFFICIENT_FUNDS",
  "message": "Source account balance is insufficient for this transfer.",
  "requestId": "req-2k3m9a1b"
}
```

The failed transfer leaves the source balance unchanged:

```sh
curl -sS http://localhost:3000/accounts/3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b/balance
```

`HTTP/1.1 200 OK`

```json
{
  "accountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
  "balance": "4000",
  "currency": "USD"
}
```

```sh
curl -sS http://localhost:3000/accounts/00000000-0000-4000-8000-000000000000/balance
```

`HTTP/1.1 404 Not Found`

```json
{
  "code": "UNKNOWN_ACCOUNT",
  "message": "Referenced account does not exist.",
  "requestId": "req-2k3m9a1c"
}
```

## 10. Invalid input

A transfer amount of `"0"` is rejected with `400 Bad Request` and
`ZERO_AMOUNT` before any database work occurs.

```sh
curl -sS -X POST http://localhost:3000/transfers \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: transfer.20260808:zero-amount-001' \
  -d '{
    "sourceAccountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
    "destinationAccountId": "7b8c9d0e-1f2a-4b3c-9d4e-5f6a7b8c9d0e",
    "amount": "0",
    "currency": "USD"
  }'
```

`HTTP/1.1 400 Bad Request`

```json
{
  "code": "ZERO_AMOUNT",
  "message": "Transfer amount must be greater than zero.",
  "requestId": "req-2k3m9a1d"
}
```

## 11. Conflicting reuse of an idempotency key

Reusing the key from examples 3 and 4 (`transfer.20260808:checking-to-savings-001`)
with a different transfer payload is rejected with `409 Conflict` and
`IDEMPOTENCY_CONFLICT`. No money moves.

```sh
curl -sS -X POST http://localhost:3000/transfers \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: transfer.20260808:checking-to-savings-001' \
  -d '{
    "sourceAccountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
    "destinationAccountId": "7b8c9d0e-1f2a-4b3c-9d4e-5f6a7b8c9d0e",
    "amount": "2000",
    "currency": "USD"
  }'
```

`HTTP/1.1 409 Conflict`

```json
{
  "code": "IDEMPOTENCY_CONFLICT",
  "message": "Idempotency-Key has already been used for a different transfer payload.",
  "requestId": "req-2k3m9a1e"
}
```

The conflict does not change financial state. The source balance remains 4000:

```sh
curl -sS http://localhost:3000/accounts/3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b/balance
```

`HTTP/1.1 200 OK`

```json
{
  "accountId": "3d4f2a7b-8c9e-4f2a-8a9b-1c2d3e4f5a6b",
  "balance": "4000",
  "currency": "USD"
}
```
